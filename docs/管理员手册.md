## 1. 架构与机制

```
                    公网服务器（Docker Compose，ubuntu 用户管理）
飞书用户 ──HTTP(S)──▶ caddy ─▶ web   平台：网页 + API + 定时任务（长期使用自动延长、到期提醒）── data/lab.db (SQLite)
飞书开放平台 ◀─长连接─ bot   机器人：欢迎卡片、私聊命令
                      proxy  mihomo：把 .env 里的家宽 ss:// 节点变成本机代理 proxy:7891
                      tunnel 登录 WebVPN，经 proxy 用 chisel 连每台 GPU，建反向隧道
                              │
            学校 WebVPN ◀─────┘ （按 IP 段封云服务器，所以必须走家宽出口）
                │
校园内网：GPU 服务器（各跑 lab-agent + chisel 服务端）
          lab-agent 访问本机 127.0.0.1:18765 ＝ 反向隧道 ＝ 平台 web:8000
```

- GPU 服务器在校园内网，公网访问不到。所以是 **Agent 主动连平台**：公网服务器上的 `tunnel` 服务登录 WebVPN（`webvpn.whut.edu.cn`，支持 WebSocket），经 `ws-` 地址用 chisel 连到每台 GPU 上的 chisel 服务端，建一条反向隧道，把平台暴露在 GPU 本机的 `127.0.0.1:18765`。
- WebVPN 封禁云服务器 IP 段，所以 `tunnel` 经**家宽（住宅宽带）节点**出口访问，WebVPN 看到的是家宽 IP。节点见第 3 节。
- 云服务器**只做管理**（隧道里只有同步 JSON 和文件浏览请求，流量很小），不提供 GPU 的外网；GPU 上外网由成员在自己的 SSH 会话里挂代理。
- 平台或隧道断开时，Agent 保持当前状态，已经在跑的实验不受影响；断开期间改的预约、密码等，隧道恢复后才生效。

### 各组件职责

| 组件 | 说明 |
|---|---|
| `web` | FastAPI：网页（原生 JS，无构建步骤）、API、Agent 接口。进程内起一个定时线程，每分钟执行「长期使用自动延长」，到 `REMINDER_HOUR` 后发「今天到期」提醒。**必须单进程运行**：预约检查和自动延长共用一把进程内的锁 |
| `bot` | 飞书长连接：新成员加入企业 / 机器人所在的群时发欢迎卡片；私聊命令 `状态` `我的` `迁移` `欢迎` |
| `tunnel` | 登录 WebVPN（自动识别滑块验证码）并维护到每台 GPU 的 chisel 隧道，状态写入 `data/tunnel/status.json` |
| `proxy` | mihomo，配置由 `deploy/gen-proxy-config.py` 根据 `.env` 的 `WEBVPN_PROXY_NODES` 生成 |
| `caddy` | 反向代理；有域名时自动申请 HTTPS 证书 |
| `lab-agent`（GPU 上） | 见下 |

### Agent 做什么

systemd 服务 `lab-agent`，只用 Python 标准库。同步间隔由平台下发（「管理 → 规则 → 页面自动刷新间隔」，默认 10 秒），每轮：

1. 上报：`nvidia-smi` 的显卡信息和占用进程（含进程所在目录）、CPU / 内存 / 磁盘、各成员账号的同步状态、旧共享账号里可复制的配置和 conda 环境；
2. 取回「这台机器此刻应该是什么样」，在本机对齐：成员账号、密码、公钥、登录组、显卡分配；
3. 执行成员发起的文件迁移（后台线程，执行中每几秒上报进度）。

另有两个后台线程：**浏览请求长轮询**（成员在网页上选择要迁移的文件时，立刻列目录 / 统计大小）和**家目录占用统计**（每 30 分钟 `du` 一遍各用户家目录，显示在日历服务器行的「磁盘占用情况」里）。

### 机制一览

| 机制 | 实现 |
|---|---|
| 每人一个账号 | Agent 用 `useradd` 创建，UID = 10000 + 平台用户 id（`UID_BASE`），所有机器一致，属于 `lab-users` 组 |
| 改用户名 | Agent 按 UID（及 GECOS 里的平台 id）识别账号：`usermod -l` 改名、移动家目录，在旧位置留一个兼容链接。账号还有进程在跑时等进程结束再改 |
| 密码登录 | 平台只存 sha512-crypt 哈希，Agent 用 `chpasswd -e` 写入 `/etc/shadow`。成员在服务器上用 `passwd` 改的会被平台覆盖；平台没设密码的账号密码处于锁定状态 |
| 公钥登录 | sshd 对 `lab-users` 只读 `/etc/ssh/lab_authorized_keys/<用户名>`，成员自己加到 `~/.ssh` 的公钥不生效 |
| 谁能 SSH 登录 | sshd 配置 `AllowGroups lab-active lab-admin`。`lab-active` 由 Agent 按「管理 → 规则 → 仅允许当天预约了该服务器显卡的成员 SSH 登录」维护：**关闭（默认）**所有成员都在组里，预约只决定能用哪些卡；**打开**只有当天预约了这台服务器的成员在组里。开关约一个同步周期内生效 |
| 只看到预约的卡 | `/etc/lab-gpu/<用户名>` 配合 `/etc/profile.d/lab-gpu.sh`（并插入 `/etc/bash.bashrc` 开头，覆盖非登录 shell）设置 `CUDA_VISIBLE_DEVICES`；没有预约时文件为空，看不到任何卡。**软限制**，成员可以自己改，所以平台同时做进程监控（见下） |
| 未预约使用告警 | 卡上有进程、但进程属主今天没预约这张卡：日历上显示 ⚠，并给本人发飞书提醒（同一人同一张卡每天一次） |
| 旧共享账号 | `--legacy-user` 指定的账号（gpu_01 的 `ubuntu`、gpu_02 的 `ubuntu602`）加入 `lab-admin` 组，保留登录权限，Agent 从不改动，**由管理员改密码、清理公钥后自用** |
| 管理员账号 | root、旧共享账号、`--admin-user` 指定的账号在 `lab-admin` 组，任何时候都能登录 |

**安全边界：** 即使云端被攻破，Agent 也只管理 `lab-users` 组里的普通账号：不碰 UID < 1000 的账号，不碰 `sudo` / `admin` / `wheel` / `lab-admin` 组成员，从不授予 sudo，从不删除用户。文件迁移只接受旧共享账号家目录和 `migration_roots` 之下的内容，保护措施见第 6 节。

### GPU 服务器上的文件

| 路径 | 内容 |
|---|---|
| `/opt/lab-agent/lab_agent.py` | Agent 本体（systemd 服务 `lab-agent`，日志 `journalctl -u lab-agent -f`） |
| `/etc/lab-agent/config.json` | Agent 配置：`server_url`、`token`、`legacy_users`、`adopt_users`、`migration_roots`、`home_base`（默认 `/home`）、`interval`、`candidate_scan_interval`、`usage_scan_interval` |
| `/etc/lab-agent/chisel.env`、服务 `lab-chisel` | chisel 服务端及其口令 |
| `/etc/ssh/sshd_config.d/00-lab.conf` | sshd 配置：`AllowGroups`、密钥路径等（写入前 `sshd -t` 校验，失败回滚） |
| `/etc/ssh/lab_authorized_keys/<用户名>`、`/etc/lab-gpu/<用户名>` | 成员公钥、分配的显卡（均由 Agent 维护） |
| `/usr/local/bin/lab-gpus`、`/etc/profile.d/lab-gpu.sh` | 成员查看 / 应用自己预约的卡 |
| `/var/lib/lab-agent/` | 迁移的进度和标记，用于中断后续传 |

## 2. 首次部署

### 2.1 创建飞书应用

在 [飞书开放平台](https://open.feishu.cn/app) 创建**企业自建应用**（自建应用只允许本企业成员授权登录，这是第一道访问控制；平台自己还有一道组织校验，见 2.3）：

1. **凭证与基础信息**：记下 `App ID` 和 `App Secret`。
2. **添加应用能力**：网页应用（桌面端和移动端主页都填平台地址）、机器人。没开机器人能力时发消息会报 `230006`。
3. **安全设置 → 重定向 URL**：添加 `<平台地址>/auth/callback`（和 `.env` 里的 `BASE_URL` 一致）。
4. **权限管理**：开通
   - 以应用的身份发消息 `im:message:send_as_bot`
   - 读取用户发给机器人的单聊消息 `im:message.p2p_msg:readonly`
   - 获取群组信息 `im:chat:readonly`（「用户进群」事件）
   - 获取通讯录基本信息 `contact:user.base:readonly`（「员工入职」事件）
5. **事件与回调 → 事件配置**：订阅方式选「使用长连接接收事件」（保存前要先把 `bot` 服务跑起来），添加事件：`im.message.receive_v1`、`im.chat.member.user.added_v1`、`contact.user.created_v3`。
6. **可用范围**：只勾选实验室成员或部门。
7. **版本管理与发布**：创建版本并发布，由企业管理员审核通过（改权限、能力后都要重新发布才生效）。

新人欢迎有两种触发方式：成员加入飞书企业（员工入职），或加入机器人所在的群（用户进群）。只想在指定的群触发，设置 `WELCOME_CHAT_IDS`。

### 2.2 部署平台（公网服务器）

前提：Ubuntu 服务器、有 sudo；安全组放行 80 / 443；要用域名的话已解析到本机并完成备案（备案前 80 / 443 会被运营商拦截）。

```bash
git clone <本仓库> lab && cd lab/deploy
sudo bash setup-server.sh      # 第一次：安装 Docker，生成 .env 后退出
vim .env                       # 填写配置（见 2.3）
sudo bash setup-server.sh      # 第二次：构建并启动全部服务（首次会下载 chisel）
```

`setup-server.sh` 做的事：安装 Docker 并配置腾讯云镜像加速、构建镜像（用腾讯云 apt / pip 源）、下载 chisel、生成 `SECRET_KEY` 和 `CHISEL_SECRET`、把管理用户加入 docker 组、注册 systemd 服务 `lab-config.path` / `lab-config.service`。

**只有 `setup-server.sh` 需要 sudo。** 之后用普通用户（`ubuntu`）即可：`.env`、`data/` 归它所有，`docker compose` 不用 sudo（加入 docker 组后要重新登录一次 SSH）。docker 组等同于 root，只给管理员账号。

**修改配置：** 所有配置都在 `deploy/.env` 一个文件里，`vim` 修改后保存，几秒内自动生效：

- `lab-config.path` 监听这个文件，变化后执行 `deploy/apply-config.sh`；
- 先校验，有错误就不应用、保持当前服务不变；
- 只重建配置有变化的容器（只改飞书配置时，tunnel 不重启，校园网连接不断）；改了家宽节点会重启 `proxy`；
- 结果写在 `deploy/data/config-apply.log`：`tail ~/lab/deploy/data/config-apply.log`。

每个容器只拿到自己需要的变量（平台容器拿不到校园网密码，tunnel 容器拿不到飞书 Secret），见 `docker-compose.yml`。值里有 `$` 或「空格 + #」时用单引号括起来。

**访问入口：** 默认用域名 `DOMAIN`，Caddy 自动申请和续期 HTTPS 证书（想用自己的证书，把 `Caddyfile` 改成 `tls /path/cert.pem /path/key.pem`）。域名还不能用时（如备案中），在 `.env` 里设置 `HTTP_SITE=http://<公网IP>` 并把 `BASE_URL` 改成同一地址，走不加密的 HTTP；域名可用后删掉 `HTTP_SITE`、把 `BASE_URL` 改回 `https://域名`，并同步修改飞书里的重定向 URL。网页顶部的 HTTP 提示条只在非 HTTPS 访问时出现。

**部署完成后：**

1. 用飞书登录平台。**第一个登录的人自动成为管理员**，请自己先登录。
2. 「管理 → 新人欢迎卡片」填好新人指南链接，点「发给我自己测试」。
3. 「管理 → 预约与迁移规则」确认各项规则（第 7 节）。
4. 添加 GPU 服务器并接入（第 5 节）。

### 2.3 `.env` 配置项

| 配置 | 说明 |
|---|---|
| `LAB_NAME` | 实验室名称，显示在页面标题和引导里 |
| `DOMAIN` / `BASE_URL` / `HTTP_SITE` | 域名、平台对外地址（飞书回调、消息卡片链接用它）、临时 HTTP 入口，见上 |
| `SECRET_KEY` | 签名登录 Cookie，自动生成，不要泄露 |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 飞书应用凭证 |
| `FEISHU_TENANT_KEY` | 可选：只允许该飞书组织的成员登录。不填则以管理员登录时记下的组织为准（见下） |
| `WELCOME_CHAT_IDS` | 可选：只对这些群（逗号分隔 chat_id）的新成员发欢迎卡片 |
| `MAX_RESERVATION_DAYS` / `MAX_ADVANCE_DAYS` | 单次预约最长天数（14）、最多提前几天（30）；管理员不受限 |
| `MAX_GPU_SHARERS` | 同一张卡同一天最多几人共用（3），管理员也受此限制 |
| `REMINDER_HOUR` | 每天几点发「今天到期」提醒（20） |
| `TZ_NAME` | 时区（Asia/Shanghai），预约按这个时区的自然日算 |
| `DEV_LOGIN` | 本地开发的免密登录，**线上必须是 0** |
| `COMPOSE_PROFILES=campus` | 启用 `proxy` 和 `tunnel`；不需要校园网接入时删掉 |
| `WEBVPN_PORTAL` / `WEBVPN_USER` / `WEBVPN_PASSWORD` | WebVPN 地址和统一身份认证账号 |
| `WEBVPN_PROXY_NODES` / `WEBVPN_PROXY` | 家宽代理节点和代理地址，见第 3 节 |
| `CHISEL_PORT` / `CHISEL_SECRET` / `CHISEL_ALLOW` / `CHISEL_FINGERPRINT` | 隧道参数，见第 3 节 |
| `REMOTE_PLATFORM_PORT` | GPU 本机上平台的端口（18765），一般不改 |
| `TUNNEL_TARGETS` | 兜底：数据库读不到服务器列表时用，一般留空（服务器在管理页添加） |
| `APT_MIRROR` / `PIP_INDEX_URL` | 构建镜像用的国内源 |

**登录范围（两道限制）：**

1. 飞书应用是企业自建应用，其他组织的人（包括个人飞书号）无法授权登录。
2. 平台再校验一次：设置了 `FEISHU_TENANT_KEY` 就以它为准；否则以**管理员最近一次登录时记下的飞书组织**为准（「管理 → 规则 → 仅允许和管理员同一个飞书组织的成员登录」，默认开）。还不知道管理员组织时（比如刚升级后管理员还没重新登录），只放行已有账号的人，陌生人一律拒绝。组织标识不是飞书后台显示的「企业编号」，由登录时自动记录。

## 3. 校园网接入

### 3.1 家宽代理

学校 WebVPN **按 IP 段封禁云服务器**（腾讯云等），直连返回「访问被拒绝」，必须经**家宽节点**出口。`proxy` 服务（mihomo）把节点变成本机代理 `proxy:7891`，`tunnel` 的 WebVPN 登录和 chisel 连接都走它。

在 `.env` 的 `WEBVPN_PROXY_NODES` 填家宽节点的 `ss://` 链接（Shadowrocket 等客户端里对节点「复制网址」），多个用逗号分隔，**第一个为主用**，不通自动切下一个：

```
WEBVPN_PROXY_NODES='ss://....#MY家宽,ss://....#备用'
```

- 这些节点是服务器自己直接连的，**和你电脑上 Shadowrocket 是否开着无关**。
- 只有家宽 / 住宅 IP 有效，机房 IP（多数「机场」节点）会被一起封。确认出口是家宽：`docker compose exec web curl -s --proxy http://proxy:7891 http://ip-api.com/line/?fields=isp`，看 ISP 是不是住宅运营商。
- **节点失效（订阅到期、流量用完、出口 IP 被封）时：** 只改 `.env` 里的 `WEBVPN_PROXY_NODES` 并保存，几十秒内自动生效，`config-apply.log` 里会有「家宽代理节点已更新」，不用改代码或重新部署。节点失效期间隧道会断，平台无法同步 GPU。
- 如果换成普通 HTTP / SOCKS5 家宽代理，可以不用 mihomo，直接把 `WEBVPN_PROXY` 改成它的地址（如 `http://用户:密码@主机:端口`）。
- 合规提醒：这是绕过学校对云 IP 的封锁，请自行确认符合学校网络使用规定。

### 3.2 WebVPN 登录与隧道

`tunnel` 用 `WEBVPN_USER` / `WEBVPN_PASSWORD`（统一身份认证账号）登录 WebVPN，代码在 `server/app/webvpn.py`：

- 密码按登录页算法 AES-128-CFB 加密后提交，**滑块验证码自动识别**，无需人工；
- 会话 Cookie 过期时自动重新登录并重连隧道；
- **账号或密码错误时立即停止**，在 `.env` 里改好保存后自动重试；
- **硬限速**：每小时最多 4 次登录尝试，跨容器重启持久生效，防止反复失败把账号 / IP 刷到被封（次数由 `tunnel.py` 读环境变量 `WEBVPN_MAX_ATTEMPTS_PER_HOUR`，要改的话需在 `docker-compose.yml` 的 tunnel 环境里加上它）。

检查状态：

```bash
docker compose logs -f tunnel                               # 出现「WebVPN 登录成功」即可
docker compose exec tunnel python -m app.tunnel status      # 各 GPU 隧道状态
docker compose exec tunnel python -m app.tunnel login-test  # 只测一次登录（排查用）
```

管理页「GPU 服务器」上方有「公网服务器 → 学校 WebVPN」的登录状态，表格里有每台 GPU 的「校园网隧道」状态。排查 WebVPN 登录也可以在自己电脑上执行 `tools/webvpn_login_test.sh <学号>`（直连校园网，只测登录）。

### 3.3 隧道的安全

- **`CHISEL_SECRET`**：公网服务器和每台 GPU 的 chisel 共用的认证口令，没有它建不了隧道。
- **防火墙**：GPU 上的 chisel 端口只放行 WebVPN 出口网段（`CHISEL_ALLOW`，默认 `59.69.127.0/24`），安装脚本会按本机启用的 ufw / firewalld / iptables 自动配置。隧道一直连不上时，先确认这台 GPU 的防火墙放行了该网段；WebVPN 出口网段变了就改 `CHISEL_ALLOW`，再重跑注册命令。
- **可选：固定指纹防中间人**。默认不校验 chisel 服务端指纹。要开启：`chisel server --keygen key.pem` 生成私钥，作为 `--chisel-key` 传给 `install.sh`（所有 GPU 用同一个），把启动时打印的指纹填进 `CHISEL_FINGERPRINT`。

## 4. 自动部署（GitHub Actions）

push 到 `master` 后，`.github/workflows/deploy.yml` 自动：

1. **检查**：Python / Shell / JS 语法检查、单元测试（`server/tests`）、启动一次平台做冒烟测试，失败不部署；
2. **同步**：rsync 把代码推到服务器，**不覆盖** `deploy/.env` 和 `deploy/data/`（由 GitHub 推而不是服务器去拉，因为国内服务器访问 GitHub 不稳定，也不用在服务器上存 GitHub 凭据）；
3. **重启**：服务器上执行 `deploy/update.sh`（重新构建、只重启代码有变化的容器、健康检查）。旧容器在新镜像构建成功前不会被替换，部署失败的日志在 GitHub Actions 页面。

**一次性配置：**

1. 生成专用部署密钥：`ssh-keygen -t ed25519 -N "" -C github-actions-deploy@zddlab -f ~/.ssh/zddlab_actions`，把公钥加到服务器（`ssh-copy-id -i ~/.ssh/zddlab_actions.pub ubuntu@<服务器IP>`）。部署用户要能执行 `docker`（在 docker 组，或有免密 sudo）。
2. 取服务器主机公钥并核对指纹（本机 `ssh-keyscan -t ed25519 <IP> | ssh-keygen -lf -` 与服务器上 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` 必须一致）。
3. 在仓库 Settings → Secrets and variables → Actions 添加：

   | Secret | 值 |
   |---|---|
   | `DEPLOY_HOST` | 服务器公网 IP |
   | `DEPLOY_USER` | `ubuntu` |
   | `DEPLOY_PATH` | `/home/ubuntu/lab` |
   | `DEPLOY_SSH_KEY` | `~/.ssh/zddlab_actions` 私钥的完整内容（含 BEGIN / END 两行） |
   | `DEPLOY_KNOWN_HOSTS` | `ssh-keyscan -t ed25519 <IP>` 的输出 |

   私钥粘贴有问题（Windows 换行、带密码短语、误贴了 `.pub`）时，工作流会在「配置 SSH」一步直接报 `DEPLOY_SSH_KEY 不是有效的 SSH 私钥`。
4. 可选：Settings → Environments 新建 `production` 并勾选 Required reviewers，每次部署需要手动批准。
5. 第一次部署仍要在服务器上手动执行 `sudo bash setup-server.sh`。

注意：

- 仓库设为 **Private**。
- **自动部署只更新公网服务器。GPU 上的 Agent 不会自动更新**，`agent/` 有改动时要在每台 GPU 上重跑一次注册命令（第 5 节）。
- 服务器上也可以手动更新：`git pull && bash deploy/update.sh`。

## 5. 接入 GPU 服务器

### 5.1 添加并安装 Agent

1. 确认 `.env` 配好 `CHISEL_SECRET`，管理页显示「公网服务器 → 学校 WebVPN：已登录」。
2. 「管理 → GPU 服务器 → + 添加服务器」，填名称和**内网地址**（要和 GPU 在校园网里的 IP 一致，隧道靠它连）。添加后直接弹出「注册命令」（以后在表格「注册命令 → 查看命令」里也能看，含这台服务器的 Token，只有管理员可见）。
3. 用以前大家共用的账号 SSH 到这台 GPU，**这个会话要能上公网**（已挂好你的代理），直接执行：

   ```bash
   curl -fsSL <平台地址>/agent/install.sh | sudo -E bash -s -- --platform-url <平台地址> --token <Token>
   ```

   `sudo -E` 把会话里的 `http_proxy` 等带给脚本，GPU 靠它下载 Agent 和 chisel；下载完就清掉代理变量，Agent 之后只经隧道访问平台。

脚本做的事：用 Token 从平台取回隧道参数 → 下载 Agent 和 chisel → 启动 chisel 服务端并放行防火墙 → 等公网服务器经 WebVPN 把隧道连进来（最多 3 分钟）→ 创建成员账号、开始上报。具体包括：

- 把旧共享账号（默认取执行 `sudo` 的账号）加入 `lab-admin` 组，保留登录权限，Agent 不再改动它；
- 创建 `lab-users` / `lab-active` / `lab-admin` 组，写 `/etc/ssh/sshd_config.d/00-lab.conf`（成员可密码或公钥登录；root 登录策略保持原样；`sshd -t` 校验失败自动回滚）；
- 列出共享账号 `~/.ssh/authorized_keys` 里的公钥，交互执行时询问是否清空（清空前备份）；
- 安装 `lab-agent`、`lab-chisel`、`lab-gpus`、`lab-gpu.sh`。

**重复执行 = 升级 / 覆盖安装**，账号和数据不受影响。Agent 不会自动更新；平台功能依赖新版 Agent 时（管理页「状态」列悬停可看每台的 Agent 版本，当前版本见 `agent/lab_agent.py` 的 `VERSION`）：

| Agent 版本 | 新增 |
|---|---|
| 0.5 | 显卡占用进程的所在目录（日历「详情」表格） |
| 0.6 | CPU / 内存 / 磁盘上报，各用户家目录占用（日历服务器行） |
| 0.7 | 迁移文件浏览器；0.7.1 起显示 `.` 开头的隐藏文件 |
| 0.7.2 | Conda 环境迁移改为「移动」（自检通过后删除共享账号里的原环境）；不再提供缓存迁移 |
| 0.7.3 | 修复迁移任务被旧任务遗留的“已完成”标记误判为完成（页面显示 0B / 0B 却没有任何文件被迁移）；过长的进度文字不再导致进度上报失败 |

旧版 Agent 与新平台兼容，只是缺少对应功能：对应位置不显示，文件浏览器会提示需要更新 Agent。

> 备用方式：当前 SSH 会话上不了公网时，在一台能进校园网的电脑上执行 `tools/add-gpu.sh <平台地址> <Token> --user ubuntu`，它把文件从你的电脑传到 GPU 再安装。

### 5.2 `install.sh` 参数

| 参数 | 说明 |
|---|---|
| `--platform-url` | 平台地址：从这里下载文件、读取隧道参数。用它就不用再写 `--server-url` 和 `--chisel-*` |
| `--token` | 这台服务器的 Token |
| `--legacy-user` | 以前大家共用的账号，可逗号分隔写多个；默认取执行 `sudo` 的账号 |
| `--adopt-user` | 迁移前就有自己本机账号的成员（用户名要和平台上的 Linux 用户名一致），见 5.3 |
| `--migration-roots` | 共享账号家目录之外、也允许成员迁移的数据目录，默认 `/lab,/data,/workspace`，不存在的忽略 |
| `--admin-user` | 其他管理员账号（加入 `lab-admin`） |
| `--root-login keep\|yes\|key\|no` | root 远程登录策略，默认 `keep`（不改） |
| `--chisel-port` / `--chisel-secret` / `--chisel-allow` / `--chisel-key` | 隧道参数，用 `--platform-url` 时自动取回 |
| `--no-sshd` | 只装 Agent 和 chisel，不改 SSH 配置 |
| `--uninstall` | 停止 Agent、移除 sshd 配置，账号和数据保留 |

### 5.3 迁移前就有自己账号的成员

有成员在迁移前就在这台机器上有自己创建的账号，又在平台上设置了**同一个** Linux 用户名：Agent 默认不碰这个账号（平台上该服务器的账号状态显示「同步失败：本机已存在同名账号」），而且该账号不在 `lab-active` 组里，会被 sshd 的 `AllowGroups` 挡在门外。

解决：重跑注册命令时加 `--adopt-user zhangsan,lisi`（或把用户名写进 `/etc/lab-agent/config.json` 的 `adopt_users` 后重启 Agent；不能是 sudo 组成员）。接管后保留原家目录和文件，但**登录密码 / 公钥以平台为准**：没在平台设密码的账号会被锁定密码登录，请先让他们在平台上设好密码或公钥。

### 5.4 收回共享账号

确认成员都迁移完、新账号能用之后：

```bash
ps -u ubuntu -o pid,etime,cmd | grep -v -- '-bash'   # 看共享账号下还有没有在跑的任务，和当事人确认
sudo passwd ubuntu                                   # 改成只有你知道的密码
cp ~/.ssh/authorized_keys ~/.ssh/authorized_keys.bak && vim ~/.ssh/authorized_keys   # 只保留你自己的公钥
```

改密码挡不住公钥登录，**清理公钥一定要做**；共享账号通常有免密 sudo，谁能登录它谁就有 root。先别关当前会话，另开终端用新密码登录确认。

## 6. 成员迁移共享账号里的环境和文件

成员在「我的账号 → 文件迁移 → 迁移环境和文件」里自助完成（首次登录的引导里也有），共享账号在此期间照常可用。管理员在「管理 → 文件迁移记录」里看全部记录，收到飞书通知。

**① 迁移环境与配置**（除 Conda 环境是移动外，其余都是复制，共享账号里的原内容不受影响）

界面从上到下：Conda、用户级软件、配置文件、共享账号的凭据（缓存不迁移），每项旁边的 ? 悬停显示说明和实际的绝对路径。

- **配置文件**（默认勾选）：`.bashrc`、`.gitconfig`、`.vimrc`、tmux、`.condarc` / pip、`.ssh/config`、Jupyter。文本里的旧家目录路径自动改成成员的家目录。
- **用户级软件**（`~/.local/bin`、`~/bin`、`pip --user` 的包）：按需勾选。
- **共享账号的凭据**（SSH 私钥、`.git-credentials`、`.netrc`、HF token）：默认不复制；不勾选时连同所在目录一起排除。
- **Conda**：默认只复制 **conda 本体**（不含环境）到成员家目录下同名目录，之后成员自己 `conda create`；确实无法重建的旧环境可以点「展开」勾选，**环境是移动**：先复制并修正路径，成员身份自检通过后，删除共享账号里的原环境（自检没通过的保留原环境，方便重试；`~/.conda/envs` 下的也支持）。conda 本体和环境里都写死了旧路径，Agent 这样处理：
  - 文本文件（脚本解释器路径、配置、`.pth` 等）：直接替换路径；
  - 二进制文件：只处理 `conda-meta` 里记录过路径占位的文件，方法和 conda 安装时一致，新路径更长时占用字符串后面的填充空间；`.pyc` 等原样复制，由 Python 自动重编译；
  - 完成后以成员身份逐个运行环境里的 python 自检，结果写在迁移记录里。

**② 迁移个人文件和目录**

成员点「添加文件或目录」，在文件浏览器里选择。浏览范围是旧共享账号家目录和 `migration_roots`，**可以进到任意一层**：

- 通过 Agent 长轮询在服务器上实时列目录，只读；显示 `.` 开头的隐藏文件，不显示符号链接和迁移程序自己的 `.lab-*` 目录，不进入属于其他成员的目录；
- 每项可选「移动」「复制」或「原地保留」（只适用于 `migration_roots` 下的数据目录）；
- 「移动」和「原地保留」会把文件从共享位置拿走：同一路径只能一个人申请，**上级或下级路径已被别人移走也算冲突**；「复制」不受限制。

**迁移时的保护措施：**

| 处理 | 原因 |
|---|---|
| 交给成员的文件和目录改为成员所有，并加上属主读写权限 | 迁移后成员可读写、删除自己的文件 |
| 移动时先把源移进只有 root 能进的暂存目录 `.lab-migrate`（700），处理完再放进家目录 | 处理过程中共享账号和成员都碰不到这些文件 |
| 复制时用目录 fd 逐级打开、不跟随符号链接；只复制属于原账号的文件或公开可读的文件 | 共享账号仍在使用，可能有人在复制过程中替换目录 |
| 放进家目录的最后一步（含备份同名文件到 `~/.lab-backup/`）以成员自己的身份执行 | 家目录里的符号链接把戏只能影响他自己 |
| 属于 root 且不公开可读的文件不移交；硬链接指向目录外私有文件的也不移交 | 防止拿到 `/etc/shadow` 等系统文件 |
| 不交付设备文件；去掉 setuid / setgid 位 | 防止借设备文件读写磁盘，或借 setuid 程序提权 |
| 先检查家目录剩余空间；中断后可续传 | 避免写满磁盘 |

**审批：** 担心有人误领或冒领「移动」「原地保留」时，打开「管理 → 规则 → 成员发起的文件迁移需要管理员确认」，申请会进入「待确认」，在「文件迁移记录」里点同意或拒绝；复制不需要确认。

**管理员批量处理（可选）：** 对需要整组共享的数据集，用命令行工具 `agent/lab_migrate.py`。它**没有**上面的保护，只处理你确认过的目录：

```bash
sudo python3 lab_migrate.py mkshared /data/shared          # 全组可读写的共享目录
sudo python3 lab_migrate.py scan /data -o migration.tsv    # 生成映射表，编辑第一列后 apply
```

## 7. 管理页与规则

「管理」页（管理员可见）：

| 区域 | 内容 |
|---|---|
| GPU 服务器 | 添加 / 编辑 / 删除服务器；状态、Agent 版本、显卡型号；**公共用户名**（迁移前共用的账号）；校园网隧道状态；注册命令和「重置 Token」（旧 Token 立即失效，在注册命令里生成新命令，重跑即可）。删除服务器会同时删除它的预约记录，GPU 上已创建的账号不删 |
| 成员 | 姓名、Linux 用户名（可改）、UID、是否有密码 / 公钥、**管理员**、**启用**。取消「启用」后各服务器上的账号会在一个同步周期内被锁定，家目录保留 |
| 文件迁移记录 | 全部迁移任务和进度，审批入口 |
| 预约与迁移规则 | 见下 |
| 新人欢迎卡片 | 标题、正文（飞书 lark_md）、按钮（每行 `文字\|链接`，`{base_url}` 代表平台地址），「发给我自己测试」 |

**预约与迁移规则**（保存在数据库，立即生效）：

| 规则 | 默认 | 说明 |
|---|---|---|
| 长期使用：到期前多少小时自动延长 | 4 | 预约最后一天 24 − 4 = 20:00 触发 |
| 每次自动延长多少天 | 7 | 也是「长期使用」首次预约的天数（不超过 `MAX_RESERVATION_DAYS`） |
| 页面自动刷新间隔（秒） | 10 | 日历、管理页的刷新间隔；Agent 同步也按它，数据才同步变新（3–600） |
| 成员发起的文件迁移需要管理员确认 | 关 | 见第 6 节 |
| 仅允许当天预约了该服务器显卡的成员 SSH 登录 | 关 | 见第 1 节「谁能 SSH 登录」。账号、密码、文件迁移不受影响 |
| 仅允许和管理员同一个飞书组织的成员登录平台 | 开 | 见 2.3 |

`.env` 里的 `MAX_RESERVATION_DAYS`、`MAX_ADVANCE_DAYS`、`MAX_GPU_SHARERS`、`REMINDER_HOUR` 不在页面上改。

### 预约规则细节（接手改代码前先读）

- 按**自然日**：开始当天 00:00 起可用，结束日 24:00 收回；一张卡一天最多 `MAX_GPU_SHARERS` 人，同一人在同一张卡上不能有重叠的预约。
- **同一人在同一张卡上首尾相接的预约合并成一条记录**（创建、修改、自动延长后都会合并；平台启动时也会对存量数据合并一次，可重复执行）。合并后备注和长期使用标记取这段里第一条还没结束的预约。
- **已经开始的预约不能改开始日期**（管理员也一样），结束日期可以改；今天之前的部分是历史，不会被改动。
- **长期使用**（数据库里是 `auto_renew`）：不填日期，从今天起预约一个周期；这张卡上本人已有的**临时**预约被覆盖（今天起的部分取消，已开始的预约只保留今天之前的历史）。每分钟检查，到触发时间自动延长一个周期；后面这张卡的共用人数已满时只延长到满员前一天；一天都延长不了就改为临时使用并通知本人。
- 到期提醒：`REMINDER_HOUR` 之后给今天到期的**临时**预约发飞书提醒（每人每天一条）。
- 管理员可以替别人预约、改别人的预约，不受天数限制，但仍受共用人数限制。

## 9. 开发、测试与数据库

本地开发：

```bash
cd server && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
DEV_LOGIN=1 .venv/bin/uvicorn app.main:app --reload     # 打开页面后输入任意名字即可登录
.venv/bin/python -m pytest tests -q                      # 单元测试
```

`DEV_LOGIN=1` 免密登录，线上不要开。测试覆盖预约规则、长期使用、自动延长、合并、Agent 同步接口、文件浏览转发、登录组织限制和 Agent 同步循环；GitHub Actions 部署前会先跑一遍。

**数据库：** SQLite（WAL）。启动时 `create_all` 自动建新表；**给已有的表加字段**要在 `server/app/db.py` 的 `_EXTRA_COLUMNS` 里登记，启动时自动 `ALTER TABLE ADD COLUMN`。改字段类型、重命名、删字段不会自动处理，需先手动迁移数据库再部署。

**前端缓存：** 静态文件带 `?v=修改时间`，页面本身 `no-cache`，部署后刷新即可看到新版。

后续想改的地方：机器人接入自己的 Agent 服务，入口在 `server/app/bot.py` 的 `handle_text()`。

## 10. 已知限制

- **显卡隔离是软限制**：`CUDA_VISIBLE_DEVICES` 可以被成员改掉，目前靠进程监控、飞书提醒和日历告警约束。需要硬隔离可以每人一个容器（`docker run --gpus device=…`）或用 cgroup。
- **不要把成员加进 docker 组**（等同 root）；确需 Docker 用 rootless docker。
- **到期后不强制结束进程**：预约结束后卡不再分配给成员（开启「仅预约者可登录」时还不能登录），已在跑的程序不会被杀。
- **校园网接入依赖个人账号和家宽节点**：`WEBVPN_USER` 账号改密码、过期、毕业，或节点订阅失效，隧道都会断，需要更新 `.env`。交接时换成接手人的账号。
- **Agent 需要手动升级**（重跑注册命令），平台升级不会自动推给 GPU。
- **长期使用可能被用来长期占卡**：目前只靠「后面满员就停止延长」来限制，可以加规则：卡长时间 0% 利用率就不再自动延长。
- **预约粒度是「天」**：按小时预约需要改数据模型和 Agent 的判断。
