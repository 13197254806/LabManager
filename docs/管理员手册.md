# 管理员手册：部署与切换

## 0. 架构

```
                     公网服务器 1.116.118.6（www.zddlab.cn）
飞书用户 ──HTTPS──▶  caddy → web（平台 + 自动续约/到期提醒）── SQLite
飞书开放平台 ◀────── bot（新人欢迎、私聊命令）
                     proxy（mihomo：家宽节点 → 本机 7891 代理）
                     tunnel ──经 proxy──▶ 学校 WebVPN ──▶ 校园内网
                       └ chisel client（经 WebVPN 的 ws- 地址连 GPU）   │
                                                                       ▼
校园内网：gpu_01 192.168.247.150 / gpu_02 192.168.247.151 …（各跑一个 chisel 服务端）
          └ lab-agent 访问本机 127.0.0.1:18765 ＝ 反向隧道 → 平台（只上报/取预约，小流量）
```

- GPU 服务器在校园内网，**不能被公网访问**。公网服务器上的 `tunnel` 服务登录学校 **WebVPN**（`webvpn.whut.edu.cn`，支持 WebSocket），经它用 **chisel** 连到每台 GPU 服务器上的 chisel 服务端，建立**一条**反向隧道，让 Agent 回连平台。
- **云服务器只做"管理"**，不接管 GPU 的外网——GPU 上外网由同学各自挂代理。所以隧道流量极小（每分钟一个同步 JSON）。
- **为什么要家宽代理（proxy 服务）**：学校 WebVPN 按 IP 段封禁云服务器（腾讯云等），直接访问一律被挡。所以经一个**家宽（住宅宽带）节点**出口，让 WebVPN 看到的是家宽 IP。实测腾讯云直连被封，经马来西亚家宽节点访问正常。
- **为什么不用 aTrust**：aTrust 同一账号只能在一处登录，公网服务器用它会把你自己电脑上的 aTrust 挤下线。现在公网服务器走 WebVPN+家宽代理，你的电脑继续用 aTrust，互不影响。
- GPU 服务器上只多了一个 chisel 服务端（systemd 服务 `lab-chisel`），用随机口令认证，防火墙只放行 WebVPN 出口网段访问它的端口。
- Agent 每分钟做三件事：
  - 上报 `nvidia-smi` 信息、各账号的同步状态和可迁移的旧目录；
  - 把本机的账号、密码、公钥、登录权限、显卡分配和平台对齐；
  - 在后台执行成员发起的文件迁移，执行期间每 2 秒上报一次进度。
- 平台不可用时，Agent 保持当前状态不变，正在进行的实验不受影响。

| 机制 | 实现 |
|---|---|
| 每人一个账号 | Agent 用 `useradd` 创建，UID = 10000 + 平台用户 id，所有机器上保持一致 |
| 改用户名 | Agent 按 UID 识别账号：执行 `usermod -l` 改名、移动家目录，在旧家目录位置留一个兼容链接。账号还有进程在跑时，会等进程结束再改 |
| 密码登录 | 平台只保存 sha512-crypt 哈希，Agent 用 `chpasswd -e` 写入 `/etc/shadow`。在服务器上用 `passwd` 改的密码会被平台覆盖 |
| 公钥登录 | sshd 对 `lab-users` 组只读取 `/etc/ssh/lab_authorized_keys/<用户名>`，用户自己加到 `~/.ssh` 里的公钥不生效 |
| 登录不依赖预约 | `AllowGroups lab-users lab-admin`：所有平台成员都能登录（被停用的成员账号会过期）。Agent 仍按当天的预约维护 `lab-active` 组，只用来让管理员看出谁今天有预约，sshd 不依赖它 |
| 只看到预约的卡 | `/etc/lab-gpu/<用户名>` 配合 `/etc/profile.d/lab-gpu.sh` 设置 `CUDA_VISIBLE_DEVICES`；没有预约时文件为空，看不到任何卡。这是**软限制**，用户可以自己改掉，所以平台同时做进程监控和告警 |
| 旧共享账号 | gpu_01 的 `ubuntu`、gpu_02 的 `ubuntu602` 保留登录权限（加入 `lab-admin` 组，不受预约限制），Agent 从不改动它们。**由管理员改密码、清理公钥后自用** |
| root 登录 | 安装脚本默认保持系统原有的 root 登录策略不变（`--root-login keep`） |

**安全边界：** 即使云端平台被攻破，Agent 也只会管理 `lab-users` 组里的普通账号。它不会碰 UID < 1000 的账号，也不会碰 `sudo`/`lab-admin` 组的成员，从不授予 sudo，也从不删除用户。文件迁移只接受旧共享账号家目录和 `migration_roots` 下的一级内容，安全措施见第 3 节。

## 1. 创建飞书应用

在 [飞书开放平台](https://open.feishu.cn/app) 创建**企业自建应用**，然后依次配置：

1. **凭证与基础信息**：记下 `App ID` 和 `App Secret`。
2. **添加应用能力**：
   - 网页应用：桌面端和移动端主页都填 `https://www.zddlab.cn`；
   - 机器人。
3. **安全设置 → 重定向 URL**：添加 `https://www.zddlab.cn/auth/callback`。
4. **权限管理**：开通以下权限（控制台里的名称可能略有不同，以控制台为准）：
   - 以应用的身份发消息（`im:message:send_as_bot`）
   - 读取用户发给机器人的单聊消息（`im:message.p2p_msg:readonly`）
   - 获取群组信息（`im:chat:readonly`）：用于「用户进群」事件
   - 获取通讯录基本信息（`contact:user.base:readonly`）：用于「员工入职」事件
5. **事件与回调 → 事件配置**：
   - 订阅方式选「**使用长连接接收事件**」。保存前需要先把第 2 节的 `bot` 服务跑起来，否则无法保存；
   - 添加以下事件：
     - 接收消息 `im.message.receive_v1`
     - 用户进群 `im.chat.member.user.added_v1`
     - 员工入职 `contact.user.created_v3`
6. **可用范围**：只勾选实验室成员或实验室部门。**不在可用范围内的人登录不了平台**，这也是第一道访问控制。
7. **版本管理与发布**：创建版本并发布，再由企业管理员审核通过。

新人欢迎有两种触发方式：

- 把成员拉进**飞书企业**时，触发「员工入职」；
- 把成员拉进**机器人所在的群**（例如实验室大群）时，触发「用户进群」。

如果只想在指定的群触发，在 `.env` 里设置 `WELCOME_CHAT_IDS`。

## 2. 部署平台（公网服务器）

前提：

- 公网服务器是 Ubuntu，你有 sudo 权限；
- 域名 `www.zddlab.cn` 已解析到 `1.116.118.6`，并已完成 ICP 备案（国内服务器未备案的域名，80/443 会被拦截）；
- 腾讯云安全组放行 80、443 端口。

```bash
git clone <本仓库> lab && cd lab/deploy        # 或者用 scp 把整个目录传上去
sudo bash setup-server.sh                      # 第一次：安装 Docker，生成 .env 后退出
vim .env                                       # 全部配置都在这一个文件：域名、飞书、校园网账号、GPU 服务器列表
sudo bash setup-server.sh                      # 第二次：构建并启动全部服务（首次会下载 chisel）
```

**只有 `setup-server.sh` 需要 sudo**（安装 Docker、注册 systemd 服务），之后的日常操作都用普通用户 `ubuntu` 完成：

- `.env` 和 `data/config-apply.log` 归 `ubuntu` 所有，直接 `vim` 修改、直接查看日志；
- `ubuntu` 被加入了 docker 组，`docker compose ...` 不用加 sudo。加入后要**重新登录一次 SSH** 才生效；
- 自动生效的服务（`lab-config.service`）也以 `ubuntu` 身份运行。

docker 组的权限等同于 root（能启动任意容器），只给管理员账号。腾讯云的 `ubuntu` 本来就有免密 sudo，所以这样做并没有放大它的权限。

`setup-server.sh` 会：

- 安装 Docker，并配置腾讯云的 Docker Hub 镜像加速；
- 构建镜像时使用腾讯云的 apt / pip 镜像源；
- 构建时下载 chisel（隧道用），并自动生成 `CHISEL_SECRET`。

HTTPS 证书由 Caddy 自动申请和续期，不需要另外申请。如果你已经在腾讯云申请了证书、想用那一份，把 `Caddyfile` 改成 `tls /path/cert.pem /path/key.pem` 即可。

**修改配置**：全部配置都在 `deploy/.env` 这一个文件里。用 `vim ~/lab/deploy/.env` 修改（不需要 sudo），**保存后几秒内自动生效**：

- 由 systemd 的 `lab-config.path` 监听这个文件，变化后执行 `apply-config.sh`；
- 先校验配置，有错误就不应用，当前服务保持不变；
- 只重建配置有变化的容器。比如只改了飞书配置，tunnel 不会重启，校园网连接不断。

每次应用的结果都写在 `deploy/data/config-apply.log` 里：

```bash
tail ~/lab/deploy/data/config-apply.log
```

每个容器只拿到自己需要的变量：平台容器拿不到校园网密码，tunnel 容器拿不到飞书 Secret，具体见 `docker-compose.yml`。值里如果有 `$` 或「空格 + #」，请用单引号括起来。

部署完成后：

1. 浏览器打开平台，用飞书登录。**第一个登录的人会自动成为管理员**，所以请你自己先登录。
2. 在「管理 → 新人欢迎卡片」里填好新人指南、知识库链接，点「发给我自己测试」。
3. 在「管理 → 预约与迁移规则」里设置自动续约的触发时间和续约天数，以及迁移是否需要你确认。
4. 数据都在 `deploy/data/` 里（`lab.db`、隧道状态）。建议每天备份 `lab.db`：
   ```bash
   sqlite3 deploy/data/lab.db ".backup '/backup/lab-$(date +%F).db'"
   ```
5. 更新版本：`git pull && bash update.sh`（不需要 sudo；配置了自动部署的话 push 即可）。
6. web 服务必须**单进程**运行（`docker-compose.yml` 默认就是）：预约冲突检查和自动续约共用一把进程内的锁，多进程会出现重复预约。

本地开发：

```bash
cd server && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
DEV_LOGIN=1 .venv/bin/uvicorn app.main:app --reload
```

`DEV_LOGIN=1` 时可以输入任意名字免密登录，**线上环境不要开**。

## 2.5 校园网接入（WebVPN + 家宽代理 + chisel 隧道）

### 必须先配好家宽代理（否则连不上 WebVPN）

学校 WebVPN **按 IP 段封禁云服务器**（腾讯云等），直接访问一律返回"访问被拒绝"。所以隧道要经一个**家宽（住宅宽带）节点**出口访问 WebVPN。`proxy` 服务用 [mihomo](https://github.com/MetaCubeX/mihomo) 把你的家宽节点变成本机代理（`proxy:7891`）。

在 `.env` 的 `WEBVPN_PROXY_NODES` 里填**家宽节点**的 `ss://` 链接（在 Shadowrocket 等客户端里对节点点「复制网址」得到）：

```
WEBVPN_PROXY_NODES='ss://....#MY家宽,ss://....#备用'
```

- 可填多个（逗号分隔），**第一个作主用**、不通自动切下一个。建议第一个填家宽节点。
- 含 `$`、`#`、空格时整行用**单引号**括起来。保存后 `proxy` 会自动重建读新节点。
- 只有**家宽/住宅 IP** 能绕过封锁；机房/数据中心 IP（大多数"机场"节点）会被一起封。确认节点出口是家宽：`docker compose exec web curl -s --proxy http://proxy:7891 http://ip-api.com/line/?fields=isp` 看 ISP 是不是住宅运营商。
- 流量很小（只有管理用的同步 JSON），家宽节点的带宽/流量完全够。

> ⚠️ **合规提醒**：这是绕过学校对云 IP 的封锁，请自行确认符合学校网络使用规定。

### WebVPN 登录

公网服务器用 `.env` 里的 `WEBVPN_USER` / `WEBVPN_PASSWORD`（统一身份认证账号，和 aTrust 相同）经家宽代理登录 WebVPN。登录代码在 `server/app/webvpn.py`：

- 密码按登录页算法用 AES-128-CFB 加密后提交；
- **滑块验证码自动识别**（拼图轮廓在背景边缘图上做相关匹配），无需人工；
- 会话 Cookie 过期时自动重新登录、重连隧道；
- **账号或密码错误时立即停止**，改好 `.env` 保存后自动重试；
- **硬限速**：每小时最多 `WEBVPN_MAX_ATTEMPTS_PER_HOUR`（默认 4）次登录尝试，跨容器重启持久生效，杜绝反复失败把账号/IP 刷到封禁。

> ✅ 公网服务器走 WebVPN+家宽代理，你自己的电脑继续用 aTrust，互不挤占，不用在自己电脑上做任何改动。

**检查是否登录成功：**

```bash
docker compose logs -f tunnel            # 出现"WebVPN 登录成功"即可
docker compose exec tunnel python -m app.tunnel status   # 各 GPU 隧道状态
docker compose exec tunnel python -m app.tunnel login-test   # 只测一次登录（排查用）
```

平台「管理 → GPU 服务器」里也有一列「校园网隧道」。断开期间 Agent 保持现状、已在跑的实验不受影响；预约/密码等改动等隧道恢复后才生效。

> **GPU 上外网**：云服务器不提供。GPU 本来就没外网，同学 SSH 上去后自己挂代理即可（和以前一样）。文件/环境迁移是同机本地操作，不需要网络。

### 隧道的安全

- **chisel 认证口令** `CHISEL_SECRET`（`setup-server.sh` 自动生成）：公网服务器和每台 GPU 的 chisel 共用，没有它无法建立隧道。
- **防火墙**：GPU 上的 chisel 端口只放行 WebVPN 的出口网段（`CHISEL_ALLOW`，默认 `59.69.127.0/24`）。如果隧道一直连不上，先确认这台 GPU 的 `ufw` 已启用并放行了该网段；学校 WebVPN 换了出口网段时，改 `CHISEL_ALLOW` 后重新 bootstrap。
- **可选：固定指纹防中间人**。默认不校验 chisel 服务端指纹。要开启：在一台装了 chisel 的机器上执行 `chisel server --keygen key.pem` 生成私钥，把它作为 `--chisel-key` 传给 bootstrap（所有 GPU 用同一个），并把对应指纹填进 `.env` 的 `CHISEL_FINGERPRINT`（启动 `chisel server --keyfile key.pem` 时会打印）。

## 2.6 自动部署（GitHub Actions）

push 到 GitHub 的 `master` 分支后，`.github/workflows/deploy.yml` 会自动执行以下步骤：

1. **检查**：Python / Shell / JS 语法检查，再启动一次平台做冒烟测试。失败就不部署。
2. **同步**：用 rsync 把代码推到服务器。不会覆盖服务器上的 `deploy/.env` 和 `deploy/data/`。之所以由 GitHub 推代码、而不是服务器去拉，是因为国内服务器访问 GitHub 不稳定，而且这样服务器上不用存 GitHub 凭据。
3. **重启**：在服务器上执行 `deploy/update.sh`，重新构建并重启，然后做健康检查；代码没变的容器不会重启，校园网连接不断。

**一次性配置：**

1. **准备部署密钥**。在自己电脑上生成一把专用密钥（已生成的话跳过）：
   ```bash
   ssh-keygen -t ed25519 -N "" -C github-actions-deploy@zddlab -f ~/.ssh/zddlab_actions
   ```
2. **把公钥加到服务器**（会让你输入一次服务器密码）：
   ```bash
   ssh-copy-id -i ~/.ssh/zddlab_actions.pub ubuntu@1.116.118.6
   ```
   部署用户要能执行 `docker`：`setup-server.sh` 已经把它加进 docker 组；不在 docker 组时，会退回用免密 sudo（腾讯云的 ubuntu 用户默认就有）。
3. **取服务器的主机公钥**，并核对指纹。下面第一条命令在自己电脑上执行，第二条在服务器上执行，两边显示的 SHA256 指纹必须一致：
   ```bash
   ssh-keyscan -t ed25519 1.116.118.6 2>/dev/null | tee /tmp/zddlab_known_hosts | ssh-keygen -lf -
   ```
   ```bash
   ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ```
4. **在 GitHub 仓库里配置 Secrets**。打开 Settings → Secrets and variables → Actions → New repository secret，添加：

   | 名称 | 值 |
   |---|---|
   | `DEPLOY_HOST` | `1.116.118.6` |
   | `DEPLOY_USER` | `ubuntu` |
   | `DEPLOY_PATH` | `/home/ubuntu/lab` |
   | `DEPLOY_SSH_KEY` | `cat ~/.ssh/zddlab_actions` 的完整输出（包括 BEGIN / END 两行） |
   | `DEPLOY_KNOWN_HOSTS` | `cat /tmp/zddlab_known_hosts` 的输出 |

5. （可选）在 Settings → Environments 里新建 `production` 并勾选 Required reviewers。这样每次部署都要你在 GitHub 上点一下批准。
6. **第一次部署仍然要在服务器上手动执行** `sudo bash setup-server.sh`，生成并填写 `.env`。之后每次 push 都会自动部署。

**注意：**

- 仓库请设为 **Private**。代码里没有密码，但服务器的部署方式没必要公开。
- 自动部署只更新公网服务器上的平台。**GPU 服务器上的 Agent 不会自动更新**，Agent 有改动时需要重新执行一次 `bootstrap`（会覆盖安装，账号和数据不受影响）。
- 数据库目前只会自动创建新表，**给已有的表加字段不会自动迁移**。以后改了数据模型，需要先在服务器上手动迁移数据库，再部署。
- 部署失败时，在 GitHub 的 Actions 页面能看到日志；服务器上旧的容器在新镜像构建成功之前不会被替换。

## 3. GPU 服务器切换流程（每台都要做）

以前大家共用一个账号：

| 服务器 | 地址 | 共享账号 |
|---|---|---|
| gpu_01 | 192.168.247.150 | `ubuntu` |
| gpu_02 | 192.168.247.151 | `ubuntu602` |

切换后，这两个账号由你接管，同学们用各自的账号登录。建议提前一周在群里通知，并约定一个切换日。

### 第 1 步：安装 Agent —— 在新服务器上执行平台给出的注册命令（**以后新增 GPU 服务器也这样做**）

1. 确认 `.env` 里配了 `CHISEL_SECRET`（`setup-server.sh` 会自动生成），且 WebVPN 已登录成功（见 2.5 节）。
2. 在平台「管理 → GPU 服务器」里添加这台机器，**填内网地址和名称**，然后点该行「注册命令」列的「查看命令」，弹窗里就是要执行的命令（含这台服务器的 Token）。
3. 用以前大家共用的账号 SSH 登录到这台 GPU 服务器。**这个 SSH 会话要能访问公网**（已连上你的网络代理），然后直接执行弹窗里的命令，不需要提前下载任何文件：

   ```bash
   curl -fsSL http://1.116.118.6/agent/install.sh | sudo -E bash -s -- --platform-url http://1.116.118.6 --token <Token>
   ```

   - `sudo -E` 会把会话里的 `http_proxy` 等环境变量带给安装脚本，GPU 靠它下载 Agent 和 chisel；
   - 旧共享账号默认取执行 `sudo` 的账号，要换成别的在末尾追加 `--legacy-user 账号名`；
   - 共享账号家目录之外大家放数据的目录，用 `--migration-roots /data` 追加。

脚本会用 Token 从平台取回 chisel 端口和口令 → 下载 Agent 和 chisel（下载完就清掉代理变量，Agent 之后只经隧道访问平台）→ 在 GPU 上启动 chisel 服务端、放行防火墙，然后公网服务器经 WebVPN 把隧道连进来，脚本等到隧道通了再继续。

> 备用方式：如果当前 SSH 会话不能上公网，可以在一台能进校园网的电脑上用 `tools/add-gpu.sh <平台地址> <Token> --user ubuntu`：它把文件从你的电脑传到 GPU 再安装。

`install.sh` 会做这些事：

- 把共享账号加入 `lab-admin` 组，**保留它的登录权限**；Agent 以后也不会改动它；
- 创建所有成员的账号，开始上报显卡信息，以及共享账号里可迁移的内容（配置、conda 环境、项目目录）；
- 写入 `/etc/ssh/sshd_config.d/00-lab.conf`：
  - 成员可以用密码或公钥登录，不需要预约（预约只决定能用哪些显卡）；
  - root 登录策略**保持原样**；
  - 写入前用 `sshd -t` 校验，失败会自动回滚；
- 检查共享账号的 `~/.ssh/authorized_keys`，列出里面的公钥。交互执行时会询问是否清空（清空前会备份）；
- 隧道模式下：
  - 安装 chisel 服务端（systemd 服务 `lab-chisel`），用 `--chisel-secret` 认证；
  - 用 `ufw` / `firewalld` / `iptables`（本机启用了哪个就配哪个）放行 WebVPN 出口网段（`--chisel-allow`）访问 chisel 端口。
  - 不改动 GPU 的外网设置：云服务器不接管 GPU 上外网，同学需要时自己在 SSH 会话里挂代理。

| 参数 | 说明 |
|---|---|
| `--platform-url` | 平台公网地址：从这里下载 Agent / chisel、读取隧道参数。用它就不需要再写 `--server-url` 和 `--chisel-*` |
| `--legacy-user` | 以前大家共用的账号，逗号分隔可以写多个；不写则取执行 `sudo` 的账号 |
| `--migration-roots` | 共享账号家目录之外，也允许成员迁移的数据目录。默认 `/lab,/data,/workspace`，不存在的会自动忽略 |
| `--admin-user` | 可选：你另外的个人管理员账号 |
| `--root-login keep\|yes\|key\|no` | root 远程登录策略。默认 `keep`，不修改 |
| `--chisel-port` / `--chisel-secret` | chisel 服务端监听端口和认证口令（用 `--platform-url` 时自动从平台取回） |
| `--chisel-allow` | 只放行这个网段访问 chisel 端口（默认 `59.69.127.0/24`，WebVPN 出口） |
| `--chisel-key` | 可选：chisel 服务端私钥文件，固定指纹防中间人（见 2.5 节） |
| `--no-sshd` | 只装 Agent 和 chisel，不改 SSH 配置 |

### 第 2 步：让同学们完成设置和迁移

把《用户指南》发到群里。同学第一次登录平台时会弹出引导：设置用户名 → 设置密码或公钥 → 迁移旧环境和文件。在「管理 → 成员」和「管理 → 文件迁移记录」里可以看到进度。

**这段时间共享账号照常可用**，同学们可以先迁移、确认新账号没问题，再停用共享账号。

迁移分两类：

**① 从共享账号复制环境与配置**（复制，共享账号不受影响）

- 配置文件：`.bashrc`、`.gitconfig`、`.vimrc`、tmux、`.condarc`、pip、`.ssh/config`、Jupyter。文本里的 `/home/ubuntu` 会改成成员的家目录；
- 用户级软件（`~/.local`、`~/bin`）、模型缓存：成员按需勾选；
- 共享账号的凭据（SSH 私钥、`.git-credentials`、`.netrc`、HF token）：默认不复制；不勾选时，连同所在目录一起排除；
- **conda**：默认只复制 **conda 本体**（不含环境）到成员的 `~/miniconda3`（保持原目录名），成员自己用 `conda create` 建新环境（GPU 上外网同学自己挂代理）。不方便重建的旧环境，也可以展开列表勾选复制，`~/.conda/envs` 下的环境同样支持。conda 本体和环境都不能直接复制，因为里面写死了 `/home/ubuntu/miniconda3`。Agent 的处理方式：
  - 文本文件（脚本开头的解释器路径、配置、`.pth` 等）：直接替换路径；
  - 二进制文件：只处理 conda 自己在 `conda-meta` 里记录过路径占位的那些文件，和 conda 安装时用的是同一种方法。新路径更长时，占用 conda 安装时留在字符串后面的填充空间。`.pyc` 等其他二进制文件原样复制，`.pyc` 会被 Python 自动判为过期并重新编译；
  - 完成后以成员身份逐个运行环境里的 python 自检，结果写在迁移记录里。

  实测：用户名比 `ubuntu` 短（`alice`）和长 8 个字符（`carolinechenxx`）时，复制后的环境都能正常 `conda activate`、导入 numpy / ssl / sqlite3、运行改写过的二进制程序。

**② 迁移个人文件和目录**

- 共享账号家目录里，以及 `--migration-roots` 下不属于任何成员的一级内容；
- 每项可以选「移动」（同一个目录只能一个人申请）、「复制」（不受限制），或「原地保留」（只适用于数据目录）。

为了保证迁移后成员对文件**有完全控制权**，并且**不会被借机提权**，Agent 会这样处理：

| 处理 | 原因 |
|---|---|
| 所有交给成员的文件和目录改为成员所有，加上属主读写权限 | 迁移后成员可以读写、删除自己的文件 |
| 移动时先把源目录移进只有 root 能进的暂存目录 `.lab-migrate`（700），处理完再放进家目录 | 处理过程中，共享账号和成员都碰不到这些文件 |
| 复制时全程用目录 fd 逐级打开、不跟随符号链接；只复制属于原账号的文件，或公开可读的文件 | 共享账号仍在使用，可能有人在复制过程中替换目录 |
| 放进家目录的最后一步（含备份原有同名文件）以成员自己的身份执行 | 家目录里的任何符号链接把戏，都只能影响他自己 |
| 属于 root 且不公开可读的文件不移交；有硬链接指向目录外私有文件的也不移交 | 防止拿到 `/etc/shadow` 等系统文件（包括脱离原文件后的旧副本） |
| 设备文件不交给成员；去掉 setuid / setgid 位 | 防止通过设备文件读写磁盘，或借 setuid 程序提权 |
| 先检查家目录剩余空间；中断后可以续传 | 避免写满磁盘；大目录可能要复制很久 |

迁移通知会发给管理员。「移动」和「原地保留」会把文件从共享位置拿走，如果担心有人误领或冒领，可以在「预约与迁移规则」里打开「迁移需要管理员确认」。复制不需要确认。

**管理员批量处理（可选）。** 对需要整组共享的数据集，可以用命令行工具 `lab_migrate.py` 处理。这个工具**没有**上面那套保护，只用来处理你确认过的目录：

```bash
sudo python3 lab_migrate.py mkshared /data/shared               # 全组可读写的共享目录
sudo python3 lab_migrate.py scan /data -o migration.tsv         # 生成映射表，编辑第一列后 apply
```

### 第 3 步：收回共享账号

确认同学们都迁移完、新账号能用之后：

```bash
ps -u ubuntu -o pid,etime,cmd | grep -v -- '-bash'   # 先看看共享账号下还有没有在跑的任务，和当事人确认
sudo passwd ubuntu                                   # 改成只有你知道的密码
# 清理同学们以前加到共享账号里的公钥：改密码挡不住公钥登录！
cp ~/.ssh/authorized_keys ~/.ssh/authorized_keys.bak && vim ~/.ssh/authorized_keys   # 只保留你自己的
```

> ⚠️ 共享账号一般有 sudo。如果 `/etc/sudoers.d/` 里有 `ubuntu ALL=(ALL) NOPASSWD:ALL` 这样的免密配置，任何能登录 ubuntu 的人都等于有 root 权限。所以清理公钥这一步一定要做。

**先不要关闭当前会话**，另开一个终端，用新密码登录一次，确认没问题。

### 回退

```bash
sudo bash install.sh --uninstall
```

这会停止 Agent，并移除 sshd 配置。账号和数据都会保留。

## 4. 日常运维

| 场景 | 操作 |
|---|---|
| 新同学 | 拉进飞书企业或实验室群后，机器人自动发欢迎卡片；同学自己登录平台完成设置即可 |
| 同学毕业 / 离开 | 「管理 → 成员」取消勾选「启用」。所有服务器上的账号会在 1 分钟内被锁定，家目录保留，由你决定何时归档 |
| 修改某人的 Linux 用户名 | 本人可以在「我的账号」里修改，你也可以在「管理 → 成员」里改。各服务器会把账号改名并移动家目录，旧路径留兼容链接 |
| 审批迁移申请 | 「管理 → 文件迁移记录」里点「同意」或「拒绝」（需先打开「迁移需要管理员确认」） |
| 成员想迁移的目录不在列表里 | 目录不在 `migration_roots` 下，或已属于某个成员。可以修改 `/etc/lab-agent/config.json` 的 `migration_roots` 后重启 Agent，或者用 `lab_migrate.py` 处理 |
| 替别人预约 / 改别人的预约 | 管理员可以直接在日历上操作，不受天数限制 |
| 服务器维护 | 用管理员身份把这台机器的卡全部预约给自己 |
| Agent 日志 | `journalctl -u lab-agent -f` |
| Token 泄露 | 「管理 → 重置 Token」，然后修改服务器上的 `/etc/lab-agent/config.json`，再 `systemctl restart lab-agent` |
| 已有的同名账号要交给 Agent 管理 | 把用户名写进 `/etc/lab-agent/config.json` 的 `adopt_users`（不能是 sudo 组成员） |
| 有人需要 apt 装系统包 | 由你用 root 安装 |
| 防暴力破解（可选） | 开了密码登录以后，建议在 GPU 服务器上装 `fail2ban`：`apt install fail2ban`，默认配置就会保护 sshd |

## 5. 已知限制与后续计划

- **显卡隔离是软限制**：`CUDA_VISIBLE_DEVICES` 可以被用户改掉。目前靠进程监控、飞书提醒和日历上的公开告警来约束。如果以后需要硬隔离，可以给每人一个容器（`docker run --gpus device=…`），或用 cgroup 限制设备访问。
- **不要把成员加进 docker 组**：docker 组等同于 root 权限。确实需要 Docker 的话，用 rootless docker。
- **到期后不会强制结束进程**：只是不能再登录。如果以后需要强制结束，可以在 Agent 里加上宽限期加自动 kill 的逻辑。
- **校园网接入依赖个人账号**：WebVPN 用的是你的统一身份认证账号。账号改密码、过期时，隧道会断开，需要更新 `.env` 的 `WEBVPN_PASSWORD`（保存即自动生效）。毕业交接时记得换成接手人的账号。WebVPN 和你自己电脑上的 aTrust 互不冲突。
- **上外网速度受公网服务器带宽限制**：大文件建议用国内镜像源，或者在校内直接下载。
- **自动续约可能被用来长期占卡**：目前只靠「后面有人约就停止续约」来限制。如果以后需要更严格，可以加一条规则：卡在一段时间内利用率一直是 0，就不再自动续约。
- **预约粒度是「天」**：如果以后需要按小时预约，需要调整数据模型和 Agent 的判断逻辑。
- **后续计划**：机器人接入自己的 Agent 服务，入口在 `server/app/bot.py` 的 `handle_text()`；闲置预约提醒（预约了但长时间 0% 利用率）。
