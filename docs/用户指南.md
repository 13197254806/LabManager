# 实验室 GPU 使用指南

> 写给实验室每位同学，可以直接导入飞书知识库。
> 平台地址：**https://www.zddlab.cn**

## 先记住这几条

- **每人一个自己的账号**登录 GPU 服务器，不再共用 `ubuntu` / `ubuntu602`。
- **用卡前先在网页上预约**，点了就生效，不用审批。登录后只能使用你预约的那几张卡，没预约的卡 `nvidia-smi` 看不到、程序也用不了。预约结束后如果你的程序还在没预约的卡上跑，平台会飞书提醒你，宽限期（默认 24 小时）一过会被自动终止，请及时续约或停掉。
- 登录服务器、改密码、迁移文件**不需要预约**。
- 服务器没有外网，需要 pip / conda / git 下载时，自己在 SSH 会话里挂代理。
- 没有 sudo。需要 apt 安装系统软件，找管理员。

## 一、第一次使用

打开平台，点「使用飞书登录」。第一次登录会弹出引导，按提示走三步（都可以先跳过，之后在「我的账号」里补）：

1. **设置 Linux 用户名**：你在所有服务器上的登录名，用姓名拼音，如 `zhangsan`。小写字母开头，只能含小写字母、数字、`-`、`_`，2–31 位；`ubuntu`、`root` 等系统名字不能用。
2. **设置登录方式**：服务器密码（至少 8 位，登录服务器用，不是飞书密码）和 SSH 公钥至少设一种。
   - 公钥免输密码。在**你自己的电脑**上执行 `ssh-keygen -t ed25519`（一路回车），再 `cat ~/.ssh/id_ed25519.pub`（Windows：`type $env:USERPROFILE\.ssh\id_ed25519.pub`），把输出的**整行**粘贴到平台。只粘贴 `.pub` 结尾的公钥，私钥不要发给任何人。
3. **迁移旧环境和文件**：把共享账号里属于你的东西搬到自己的账号，见第五节。

之后在「我的账号」页可以随时修改密码、增删公钥、查看各服务器的登录命令和账号状态。

## 二、预约 GPU

打开「GPU 日历」：每一行是一张显卡，每一列是一天，色块是已有的预约。**点日历上的空白格子**即可预约。

预约时先选「使用方式」：

| | 临时使用 | 长期使用 |
|---|---|---|
| 怎么选 | 选开始日期（含）和结束日期（含） | 不用选日期 |
| 效果 | 到结束日 24:00 后卡不再分配给你 | 从**今天**起预约 7 天，在最后一天晚上 8 点自动再延长 7 天（具体时长以页面提示为准），并飞书通知你 |
| 适合 | 有明确时间段的实验 | 长期占一张卡，不想每周手动续 |

**长期使用的细节：**

- 你在这张卡上已有的临时预约会被它覆盖（今天之前的使用记录保留）；
- 后面这张卡的共用人数满了，只延长到满员前一天；一天都延长不了，就自动改为临时使用并通知你；
- 实验跑完了，请改为临时使用或直接释放。

**其他操作**（点自己的色块）：

| 想做什么 | 怎么做 |
|---|---|
| 延长 / 缩短 | 改结束日期后保存。已经开始的预约不能改开始日期 |
| 提前释放 | 「立即释放」（没开始的是「取消预约」） |
| 改成长期 / 临时使用 | 勾选或取消「长期使用」，也可以在「我的账号 → 我的预约」里改 |

**规则：**

- 按自然日算：开始当天 00:00 起可用，结束日 24:00 收回；
- 单次最长 14 天，最多提前 30 天预约（长期使用自动延长不受这个限制）；
- 一张卡同一天最多 **3 人共用**，共用时色块上下并排显示；满了约不上，页面会说是谁约的；
- 你自己在同一张卡上不能有重叠的预约；首尾相接的会自动合并成一个色块；
- 用完请及时释放。

**读日历：**

- 色块里是预约人的头像和名字：**带深色粗边框的是你自己的预约**，其他人的没有边框；带循环箭头图标的是长期使用；鼠标放在色块上能看预约人、日期和备注；
- **日期可以直接拖着改**：鼠标放到自己还没结束的预约块上，两侧边缘会出现小把手，按住左右拖动，松手即提交（会提示新的日期；按 Esc 取消）：
  - 拖**右边缘**改结束日期；
  - 拖**左边缘**改开始日期（只有今天及以后才开始的预约；已经过去的日期不能改）；
  - 已经开始、跨过今天的预约，向右拖「今天」处的左边缘，会把它**拆成两条**：已过去的部分保留为历史，后面的部分从你放开的那天重新开始，中间的日子释放；
  - 拖到和你自己在这张卡上的另一条预约**重叠或相邻**，两条会自动**合并**成一条（备注、长期使用以靠左、第一条还没结束的为准）；
  - 撞上别人的预约（共用人数已满）或超过单次最长天数时会被拒绝并提示原因，色块恢复原样；也可以点色块在详情里改；
- 今天之前的日期有灰色斜线，色块里已结束的部分颜色更浅；今天这一列有蓝色高亮；
- 点服务器名可折叠 / 展开它的显卡；左上角可以点年月选择、翻月；服务器名下面的「今天空闲 N」是今天还没人预约的卡数；
- 服务器行显示 CPU、内存、磁盘占用（进度条越满颜色越深：70% 起变橙，90% 起变红）；磁盘右边的蓝色「占用情况」可看各用户占了多少；
- 显卡行显示实时利用率和显存，点右侧蓝色「详情」看占用这张卡的进程（用户、进程号、所在目录、显存）；
- 蓝色的「占用情况」「详情」鼠标放上去就显示气泡，移开消失；**点击一下**气泡就固定住（边框变蓝），再点别处才消失；
- 显卡行右上角的 ⚠ 表示有人没预约却在用这张卡；
- 页面按管理员设置的间隔（默认 10 秒）自动刷新。

## 三、登录服务器并使用显卡

```bash
ssh zhangsan@192.168.247.150
```

输入你在平台上设的密码（设了公钥就自动用公钥）。需要在**实验室内网**（或学校 VPN）里。新设的密码、公钥、预约在**十几秒到 1 分钟**内同步到服务器。不要再用 `ubuntu` / `ubuntu602`。

在自己电脑的 `~/.ssh/config` 里配一下，之后 `ssh gpu_01` 即可，VS Code Remote-SSH 也能用：

```
Host gpu_01
    HostName 192.168.247.150
    User zhangsan
```

**使用显卡：**

```bash
lab-gpus                          # 看今天你在这台机器预约了哪些卡
eval "$(lab-gpus --export)"       # 预约变了之后，刷新当前终端
```

1. 登录时系统按预约自动设置 `CUDA_VISIBLE_DEVICES`，**程序里的卡号从 0 重新编号**：预约了 GPU2、GPU3，程序里是 `cuda:0`、`cuda:1`。不要写死卡号，也不要自己改这个变量；
2. 已经打开的终端不会自动更新，重新登录或执行上面的 `eval`；
3. 长时间训练放在 `tmux` / `screen` 里；
4. 没预约的卡打不开，新起的程序在上面跑不了；
5. 预约到期后卡不再分配给你。**已经在跑的程序有缓冲期**（默认 24 小时，具体以管理员设置为准）：期间机器人会飞书提醒你、日历上出现 ⚠，缓冲期一过程序会被自动终止（未保存的结果会丢失），所以到期前请续约或把结果存好。如果别人已经预约了这张卡，请尽快结束。

## 四、文件与上外网

| 位置 | 用途 |
|---|---|
| `/home/<你的用户名>` | 代码、conda、迁移过来的文件，只有你和管理员能访问 |
| `/data/shared` 等共享目录 | 公共数据集、模型权重，全组可用 |

以前代码里写死的 `/home/ubuntu/...` 路径，迁移后请改成新路径（配置文件和 conda 里的路径已自动改好，你自己的代码不会）。

**上外网：** 服务器没有外网，实验室平台也不提供代理。在你自己的 SSH 会话里挂上自己的代理，例如：

```bash
export http_proxy=http://127.0.0.1:端口 https_proxy=http://127.0.0.1:端口
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple   # 建议配合国内镜像
```

端口是你自己代理监听的端口，怎么把代理转发进服务器问管理员或师兄弟。

## 五、迁移旧环境和文件

入口：引导的第 3 步，或「我的账号 → 文件迁移 → 迁移环境和文件」。先选服务器，分两部分：

**① 迁移环境与配置**

除 Conda 环境是**移动**（迁移并自检通过后，原环境会从共享账号里移走）外，其它项都是**复制**，共享账号里的原内容不受影响。

从上到下依次是：

| 选项 | 默认 | 说明 |
|---|---|---|
| Conda | 本体勾选 | 本体是复制，不含环境，路径自动改好。已有环境点「展开」可选，是**移动**；推荐自己 `conda create` 新建 |
| 用户级软件（`~/.local/bin`、`~/bin`、`pip --user` 的包） | 不勾选 | 需要再选 |
| 配置文件（`.bashrc`、`.gitconfig`、`.vimrc`、tmux、`.condarc` / pip、`.ssh/config`、Jupyter） | 勾选 | 文件里的 `/home/ubuntu` 自动改成你的家目录 |
| 共享账号的凭据（SSH 私钥、`.git-credentials`、`.netrc`、HF token） | 不勾选 | 这是大家共用的密钥，建议换成自己的 |

每个选项旁边的 ? 悬停可以看说明和服务器上的实际路径。apt 装的软件（git、vim、gcc、CUDA 等）全系统共享，不用迁移。迁移完成后重新登录，`conda` 就能用；之后自己建环境：

```bash
conda create -n myenv python=3.11 && conda activate myenv
```

**② 迁移我的文件和目录**

点「添加文件或目录」，在弹出的文件浏览器里打开共享账号家目录（如 `/home/ubuntu`）或数据目录（如 `/data`），进到任意一层，点「选择」。可以添加多项，**只添加自己的**。每项选一种方式：

| 方式 | 效果 | 适合 |
|---|---|---|
| 移动 | 搬到你的家目录，其他人就看不到了；同一块磁盘上瞬间完成 | 自己的项目、实验结果 |
| 复制 | 复制一份到你的家目录，原文件保留 | 大家都在用的公共代码 / 数据 |
| 原地保留 | 文件留在原处，改为归你所有，家目录里建一个快捷方式（只适用于 `/data` 等数据目录） | 几百 GB 的数据集 |

- **迁移前先停掉正在用这些文件的程序。**
- 「移动」和「原地保留」每个路径只能一个人申请（它的上级或下级被别人移走了也不行），所有记录管理员都能看到。
- 迁移在服务器后台进行，可以关页面。进度看顶部的「迁移中」标签或「我的账号 → 文件迁移」，私聊机器人发「迁移」也行，完成后会收到通知。
- 完成后文件都归你所有。你家目录里原来的同名文件会备份到 `~/.lab-backup/`。
- 可以分多次做。

## 六、修改用户名

「我的账号 → 服务器账号」点「修改」，约 1 分钟内各服务器同步：账号改名，家目录从 `/home/旧名` 搬到 `/home/新名`（旧路径留一个快捷方式）。迁移过来的 conda 环境、`.bashrc` 里的 conda 初始化、Jupyter kernel、venv 等写死了旧路径的地方，会在后台自动改成新路径，改名后照常使用；你自己代码里写死的 `/home/旧名/...` 靠那个快捷方式继续可用，建议顺手改成 `~` 或新路径（以后别人用了这个旧用户名，快捷方式会被收回）。某台服务器上你还有程序在跑时，会等程序结束再改，页面显示「等待生效」；迁移进行中不能改名。

## 八、常见问题

**登录提示 `Permission denied`？** 依次检查：用户名是不是你自己的（不是 ubuntu）；密码是不是平台上设的；改动后是否已经等了一会儿；如果管理员开启了「仅预约者可登录」，今天在这台服务器上有没有预约。

**`pip install` / `git clone` 连不上？** 服务器没有外网。确认当前会话里挂了自己的代理且端口对；内网地址用 `no_proxy` 排除。

**迁移后 `conda activate` 找不到 conda？** 重新登录一次；没迁移 `.bashrc` 的话执行 `~/anaconda3/bin/conda init bash`（目录名和共享账号里的 conda 目录一致）再重新登录。

**迁移完成提示「有文件未迁移」？** 这些文件属于 root 且不公开可读，或和系统文件是同一个文件（硬链接），出于安全不交给个人，通常不影响使用，需要的话找管理员。

**提示「二进制文件中的路径无法自动修正」？** 你的用户名比原账号名长很多，个别程序里的路径放不下，很少见。用这个环境出问题时，用 `conda env export` 导出后重建，或找管理员。

**文件浏览器提示「没有及时响应」？** 这台服务器的 Agent 需要更新，找管理员。

**在服务器上用 `passwd` 改了密码，过会儿又变回去了？** 密码以平台为准，到「我的账号 → 服务器密码」里改。

**能把账号借给实验室外的人吗？** 不能。外部合作者需要用卡，请联系管理员。
