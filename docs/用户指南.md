# 实验室 GPU 使用指南

> 写给实验室每一位同学，可以直接导入飞书知识库。
> 平台地址：**https://www.zddlab.cn**；服务器列表见文末。

## 为什么要改

以前大家共用一个账号登录 GPU 服务器（gpu_01 用 `ubuntu`，gpu_02 用 `ubuntu602`），经常出现几个问题：

- 几个人抢同一张卡；
- 文件和 conda 环境混在一起，分不清是谁的；
- 密码流传到了实验室外面。

从现在起：

- **每个人用自己的账号登录**。原来的共享账号由管理员接管，改密码后不再对外开放；
- **用卡之前先在网页上预约**，点了就生效，不需要审批；所有人随时都能看到谁在用哪张卡；
- **登录服务器、迁移文件不需要预约**；预约只决定能用哪些显卡：登录后，程序自动只能看到你当天预约的那几张卡，没有预约就看不到任何卡。

## 一、第一次使用（约 10 分钟）

在浏览器或飞书里打开 **https://www.zddlab.cn**，点「使用飞书登录」。第一次登录时，页面会弹出引导，按提示完成三步。

### 1. 设置 Linux 用户名

这是你在所有 GPU 服务器上的登录名，建议用姓名拼音，比如 `zhangsan`。之后可以修改，见第五节。

### 2. 设置登录方式（密码和公钥至少设一种）

- **登录密码**：至少 8 位，要同时包含字母和数字。所有服务器通用。
- **SSH 公钥**（可选，设置后登录不用输密码）。在**你自己的电脑**上执行：

  ```bash
  ssh-keygen -t ed25519          # 一路回车；如果提示已存在就跳过
  cat ~/.ssh/id_ed25519.pub      # Windows：type $env:USERPROFILE\.ssh\id_ed25519.pub
  ```

  把输出的**一整行**粘贴到平台上。⚠️ 只粘贴 `.pub` 结尾的**公钥**，私钥永远不要发给任何人。

### 3. 迁移旧环境和文件（可选，强烈建议做）

引导页会按服务器列出共享账号（`ubuntu` / `ubuntu602`）里的内容，分两部分。

**① 从共享账号复制环境与配置**

这一部分是**复制**，共享账号里的原内容不受影响，其他同学也可以复制同样的内容。

| 内容 | 默认 | 说明 |
|---|---|---|
| 配置文件：`.bashrc`、`.gitconfig`、`.vimrc`、tmux、`.condarc` / pip 配置、`.ssh/config`、Jupyter | 勾选 | 文件里写的 `/home/ubuntu` 会自动改成你的家目录 |
| 用户级软件：`~/.local/bin`、`~/bin`、`pip --user` 装的包 | 不勾选 | 需要时勾选 |
| 缓存：Hugging Face、PyTorch 模型缓存 | 不勾选 | 体积大，需要时再选 |
| 共享账号的凭据：SSH 私钥、`.git-credentials`、`.netrc`、HF token | 不勾选 | 这是大家共用的密钥，**建议换成自己的** |
| **conda 本体** | 勾选 | 复制到 `~/miniconda3`（保持原来的目录名），**不含任何环境**，路径自动改好 |
| conda 旧环境 | 不勾选，折叠在列表里 | 推荐自己新建环境（见下）；确实不方便重建的旧环境，可以展开列表勾选复制，路径同样会自动修正并自检 |

迁移完成后重新登录，`conda` 就能用了。之后自己新建环境：

```bash
conda create -n myenv python=3.11
conda activate myenv
pip install torch ...
```

GPU 服务器本身不能访问外网，`pip`、`conda`、`git clone` 需要先在自己的 SSH 会话里挂上代理（见第六节）。

> apt 安装的软件（git、vim、tmux、gcc、CUDA 等）是全系统共享的，新账号直接可用，不需要迁移。

**② 迁移我的文件和目录**

这里列出共享账号家目录里（比如 `/home/ubuntu/zhangsan_proj`），以及数据目录（比如 `/data`）下**还没归属任何人**的文件和目录。**只勾选自己的**，每一项可以选迁移方式：

| 方式 | 效果 | 适合 |
|---|---|---|
| **移动** | 从共享位置搬到 `~/目录名`，其他人就看不到了。同一块磁盘上瞬间完成 | 自己的项目代码、实验结果 |
| **复制** | 复制一份到 `~/目录名`，原文件保留 | 大家都用的公共代码 / 数据 |
| **原地保留** | 文件留在原处，改为归你所有，在 `~` 下建一个快捷方式（只适用于 `/data` 等数据目录） | 几百 GB 的数据集 |

> ⚠️ **迁移前请先停掉正在使用这些文件的程序**，比如还在共享账号下跑着的训练。
> ⚠️ **只迁移自己的目录。** 「移动」和「原地保留」每个目录只能有一个人申请，所有记录管理员都能看到。

迁移在服务器**后台**进行，不用一直开着网页：

- 进度（阶段、已复制多少、速度、剩余时间）可以在顶部的 **📦** 或「我的账号 → 文件迁移」里随时查看；
- 也可以私聊机器人，发送「迁移」查看；
- 完成后机器人会通知你。

迁移完成后，所有文件都归你所有，你都能读写和删除。你家目录里原来的同名文件（比如新账号自带的 `.bashrc`）会自动备份到 `~/.lab-backup/`。

引导里任何一步都可以先跳过，以后在「我的账号 → 文件迁移 → 迁移环境和文件」里补做，也可以分多次做（比如之后再追加一个 conda 环境）。

## 二、预约 GPU

打开「GPU 日历」：每一行是一张显卡，每一列是一天，色块表示已经有人预约。

| 操作 | 方法 |
|---|---|
| 预约 | 点空白格子，或点右上角「+ 预约 GPU」。可以一次选同一台机器上的多张卡 |
| 续约 / 修改日期 | 点自己的色块，改结束日期后保存 |
| 提前释放 | 点自己的色块，点「立即释放」或「取消预约」 |
| 自动续约 | 预约时勾选，或之后在色块详情、「我的预约」里打开。日历上带 🔁 的就是开了自动续约 |
| 查看实时占用 | 每行开头显示这张卡当前的利用率和显存，每分钟刷新 |

**规则：**

- 按**自然日**预约：开始那天 00:00 起可以使用这张卡，结束那天 24:00 后不再分配给你（登录不受影响）；
- 单次最长 **14 天**，最多提前 **30 天**预约；
- 一张卡同一天只能属于一个人。冲突时页面会提示是谁约的；
- 用完请**及时释放**。

### 自动续约

开启后，系统会在**到期前 24 小时**自动把预约**延长 7 天**，并用飞书通知你（具体时长由管理员设置，以页面上显示的为准）。

- 如果后面已经有人预约了这张卡，只会延长到对方预约的前一天；
- 如果一天都延长不了，系统会关闭这条预约的自动续约，并通知你；
- 实验跑完了，请记得**关闭自动续约或直接释放**。

## 三、登录服务器

```bash
ssh zhangsan@192.168.247.150
```

然后输入你在平台上设置的密码；如果添加了公钥，会自动用公钥登录。

- 需要在**实验室内网**（或学校 VPN）里；
- 登录**不需要预约**；没有预约时登录后看不到任何显卡；
- 新的预约、密码、公钥在 **1 分钟左右**后生效；
- **不要再用 `ubuntu` / `ubuntu602` 登录**，这两个账号的密码已经改了。

推荐在自己电脑的 `~/.ssh/config` 里配置好，之后直接 `ssh gpu_01` 就能登录，VS Code Remote-SSH 也能直接用：

```
Host gpu_01
    HostName 192.168.247.150
    User zhangsan

Host gpu_02
    HostName 192.168.247.151
    User zhangsan
```

## 四、使用显卡

登录时，系统会根据你的预约自动设置 `CUDA_VISIBLE_DEVICES`，你的程序只能看到预约的那几张卡。

```bash
lab-gpus        # 查看今天你在这台机器上预约了哪些卡
```

1. **程序里的卡号从 0 开始重新编号。** 比如你预约了 GPU2 和 GPU3，程序里看到的是 `cuda:0` 和 `cuda:1`。不要在代码里写死卡号，也不要自己改 `CUDA_VISIBLE_DEVICES`。
2. **预约变化后，已经打开的终端不会自动更新。** 重新登录，或者执行：`eval "$(lab-gpus --export)"`。
3. 长时间的训练请放在 `tmux` 或 `screen` 里跑。
4. 如果你在**没有预约的卡**上跑程序，机器人会提醒你，日历上那张卡也会显示「⚠ 未预约使用」。

预约到期后，第二天 00:00 起**不能再登录**；**已经在跑的程序不会被强制结束**，但如果别人已经预约了这张卡，请尽快结束。

## 五、修改用户名

在「我的账号 → 服务器账号」里点「修改」。大约 1 分钟内，所有服务器都会同步生效：

- 账号改名，家目录从 `/home/旧名` 移到 `/home/新名`，`/home/旧名` 会保留一个指向新家目录的快捷方式；
- 如果你在某台服务器上**还有程序在跑**，那台服务器会等程序全部结束后再改名，页面上会显示「等待生效」；
- 文件迁移进行中时不能改名。

## 六、文件与数据

| 位置 | 用途 | 谁能访问 |
|---|---|---|
| `/home/<你的用户名>` | 代码、conda、迁移过来的文件 | 只有你（以及管理员） |
| `/data/shared` 等共享目录 | 公共数据集、模型权重 | 全组 |

- **没有 sudo 权限。** 软件用 conda / pip 装在自己的目录下。确实需要 apt 安装系统软件时，请找管理员。
- 以前代码里写死的 `/home/ubuntu/...` 路径，迁移后请改成新路径。配置文件和 conda 里的路径已经自动改好了，**你自己的代码不会自动改**。

### 上外网

GPU 服务器本身不能访问外网，需要 pip / conda / git 下载时，**和以前一样，在自己的 SSH 会话里挂上你自己的代理**（实验室平台不接管 GPU 的外网）。例如在当前会话里设置：

```bash
export http_proxy=http://127.0.0.1:端口 https_proxy=http://127.0.0.1:端口
```

（端口是你自己的代理监听的端口；具体怎么把代理转发进 GPU 服务器，问一下管理员或师兄弟。）建议配合国内镜像源：

```bash
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

## 八、常见问题

**Q：登录提示 `Permission denied`？**

按顺序检查：

1. 今天在这台服务器上有没有预约；
2. 用户名是不是你自己的（不是 ubuntu）；
3. 密码是不是平台上设置的那个；
4. 改动后是否已经等了 1 分钟。

**Q：`pip install` / `git clone` 连不上或超时？**
GPU 服务器没有外网，实验室平台也不提供代理。先确认你在这个 SSH 会话里挂上了自己的代理（见「上外网」），并且代理端口填对；内网地址请直连，可以用 `no_proxy` 排除。

**Q：迁移后 `conda activate` 提示找不到 conda？**
重新登录一次，`.bashrc` 里的 conda 初始化才会生效。如果你没有迁移 `.bashrc`，执行一次 `~/miniconda3/bin/conda init bash`，再重新登录。

**Q：迁移完成提示「有文件未迁移 / 未改归属」？**
这些文件属于 root 且不公开可读，或者和系统文件是同一个文件（硬链接）。为了安全，系统不会把它们交给个人。通常不影响使用，确实需要的话请联系管理员。

**Q：迁移完成提示「有二进制文件中的路径无法自动修正」？**
说明你的用户名比原账号名长太多，个别程序里的路径放不下。这种情况很少见；如果用这个环境时遇到问题，可以用 `conda env export` 导出后重建，或者联系管理员。

**Q：在服务器上用 `passwd` 改了密码，过一会儿又变回去了？**
密码以平台为准，请到「我的账号 → 登录密码」里修改。

**Q：能把账号借给实验室外的人用吗？**
**不能。** 服务器只认平台上登记的公钥，也请不要把密码告诉别人。外部合作者需要用卡，请联系管理员。
